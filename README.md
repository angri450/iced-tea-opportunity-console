# 冰红茶机会台

康师傅冰红茶的热梗机会判定台。一个梗一张判定卡，卡上给一个可执行动作，动作旁边是能点开的原文，卡底记放行人与回填结果。

页面在线地址：<https://49.232.197.22:19052/>

本仓库收录三样东西：可运行的网页、判定规则的四份需求文档、一个走腾讯云元宝搜索 MCP 通道的检索脚本。网页里另有一块包装整活台，把判定结果做成能转动的 3D 瓶身贴纸模型，用来回答「贴上瓶身长什么样」。

## 一、它回答什么

1. 这个梗的讨论是否仍在持续，依据是哪几条原文。
2. 冰红茶能不能挂上去，梗里的时刻能不能让产品出场。
3. 品牌是否已经用过这个梗，竞品有没有用。
4. 语境与素材能不能用，争议在哪里。
5. 现在做内容、改包装还是只观察。

平台不预测热度，也不给概率。窗口档位在拿到量级数据之前一律标未知，改造与新品全部走人工入口。

## 三、怎么跑

```bash
cd antd-demo
npm install
npm run dev      # 开发服务器
npm run build    # 打包到 dist/
node server.mjs  # 静态服务，默认监听 127.0.0.1:19053，HTTPS 由本机 Caddy 终止
```

## 四、数据从哪来

四个示例梗的判定与链接来自 2026-11-20 的实检，检索走腾讯云元宝搜索的 MCP 通道。仓库自带的 HTTP 通道在同一把密钥下返回 `UnauthorizedOperation`，因此 `tools/mcp_search.py` 只走 `/Mcp`。

链接做过可达性检查，打不开的不计入证据。示例数据在页面上标「示例数据，非实测投放」，不代表康师傅真实决策。

## 五、判定怎么算

代码算票，模型只把摘要读成标签，人做放行。

1. 内容响应，讨论仍在持续、场景挂靠、风险可接受三项通过即可。
2. 现有产品改造，再加窗口覆盖交付周期、增量价值不是存量重复。
3. 新品探索，再加窗口覆盖 180 天、该梗二次升温或跨季复现。
4. 任一项未知，不进自动建议，走人工放行并记录放行人。

示例里四个梗没有一个四项全绿，所以没有内容响应建议。平台宁可少给建议，不构造机会。

## 六、包装整活台

判定卡回答哪个梗能用，包装整活台回答贴上瓶身是什么样。瓶身按 build123d 旋转成形的尺寸建，直径 66 毫米、高 196 毫米，装 500 毫升时液面在 170.69 毫米。右侧 13 个场景里，8 个挂在检索到的梗上并带原文链接，5 个是设计稿。贴纸只改瓶身正面，不改标签、不改瓶型。

## 七、网页做了什么

1. 深色模式跟随系统，可手动切换，选择记住。
2. 字号用 rem，跟随系统文字缩放，320 像素宽加 200% 字号不出现横向滚动。
3. 列表与判定卡切换用 View Transitions，焦点跟着新视图走。
4. 手机导航是抽屉，带遮罩、Escape 关闭、焦点回位、背景 `inert`。
5. 表单必填项有行内校验与读屏播报。
6. 键位可走通：跳过链接、菜单、表格区域、卡片按钮。

改动参照 Modern Web Guidance（Chrome、Edge、Firefox、MDN 联合维护）。细节写在 `antd-demo/README.md`。
